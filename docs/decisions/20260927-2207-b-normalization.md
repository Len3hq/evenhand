# Normalization: a joint ridge model, λ by leave-one-out, and honesty about signal

- Status: accepted
- Date: 2026-09-27 · Owner: B (built by the team's A under the whole-app plan)

## Context

T2 requires "cross judge normalization, with the method documented"; the Normalization Proof bonus asks for it "on the fixture data", documented rigorously. BUILD-PLAN §7 chose a joint additive model with ridge penalties (decision 10) over per-judge z-scores.

## Decision

- Implement BUILD-PLAN §7.2 as planned, in the pure engine: `s = μ + q_p + b_j + ε`, ridge penalties λ_b and λ_q, exact Cholesky solve, posterior SDs from the inverse, tie groups without chaining.
- λ by exact leave-one-out error. The planned grid (0.25–8) was **widened to 0.125–64** after both edges were hit (synthetic events chose 0.25; the fixtures' error was still falling at 8). The result carries `atEdge`, so a clipped choice is reported, never silent.
- Report the **mean-only baseline** (predict each review by the others' mean) beside the model's error. On the fixtures the model gains 0.9%: the data carries little signal about project quality, and the proof and JUDGING.md say so plainly. The ranking is presented with tie groups (2 on the fixtures), not as 40 confident ranks.
- Rows are summed in a fixed order so results are bit-for-bit reproducible from the same reviews.
- The proof (`docs/proof/normalization.md`) is generated by code and checked by a test against that code; Prettier leaves it alone (it is generated, like the API schema).

## Consequences (including what we gave up)

- On data like the fixtures, the portal will say "these projects cannot be told apart" more often than a raw average would. That is the point, but organisers need to read tie groups, and per-track prizes are safer than one overall order.
- Judge scale is not modelled; Bradley–Terry is not offered (no pairwise data).
- Ranking runs, receipts and publishing in the portal are the next step (9b); this ADR covers the method.

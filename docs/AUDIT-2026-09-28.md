## 3. What is strong (don't break it in the last hours)

- **Isolation:** every service decides from the caller _before_ looking the object up. Unknown and forbidden get the same 403. There is a 451-row matrix across 7 kinds of actor.
- **Normalization:**
  - Mathematically correct: the intercept is unpenalised, the leave-one-out shortcut `e/(1−h)` is exact for fixed λ, the posterior variance is `σ²(inv₀₀ + inv_qq + 2·inv₀q)`, and tie groups don't chain.
  - Deterministic: rows are sorted before summing, so results are bit-identical for any input order.
  - The proof is honest. On the fixtures the model beats a mean-only baseline by only 0.9% and chooses heavy shrinkage (λ_b = 32, λ_q = 16). On synthetic data it beats raw means (ρ 0.920 vs 0.896, and 0.897 vs 0.772 with stronger judge bias) and z-scores (0.736).
- **Rankings:** runs are hashed (inputs and output), publishing is refused if inputs changed (`ranking_stale`), and projects with fewer than 2 reviews are listed, not ranked.
- **Duplicates:** confirm, dismiss and reopen use row locks, an atomic pending→decided transition, and protection against chained merges. Undo is exact.
- **Web security:** CSP with a per-request nonce and `strict-dynamic`, a validated `?next=` return path, and CSV formula neutralising.
- **Docs:** detailed and honest, with a "What works today" table that matches the code.

## 4. Findings and fixes

### P0: before the freeze

**P0-1. CI is red on `main` (the last two commits).**
The `offline drill` job fails with `No such image: postgres:16@sha256:…`. `tests/offline/drill.sh` runs `compose build` (step 2) and later `compose up --pull never`, but never pulls the `db` image, which is pulled rather than built. It works on laptops that already have Postgres cached; on a fresh CI runner it can't.
**Fix (1 line):** in step 2, after `compose build --quiet`, add `compose pull --quiet db`. _Owner A, 5 min._

**P0-2. API tests are flaky on macOS: fix ready, uncommitted.**
`createTestApp()` handed supertest the bare server, so supertest listens on a new random port for each request, on all interfaces, then connects to `127.0.0.1:<port>`. On macOS another process can hold that port number on `127.0.0.1` alone, and the request goes to that process instead. The result is random 404s, 401s and 400s in whichever test is running (CI on Linux never sees it).
**Fix:** `tests/api/helpers.ts` now listens once on `127.0.0.1` and points supertest at that address (in the working tree, not committed). Verified 665/665 twice. _Review and commit, 5 min._

**P0-3. Track isolation: a judge keeps projects from a track the organiser removed.**
Demonstrated on the running stack. Move jdg_24 from Developer tools to another track with `PUT /api/events/evt_01/judges/jdg_24/tracks`: jdg_24's queue still lists "Dry Compass" (Developer tools), `GET /api/judge/reviews/:id` returns 200 with the project, and while judging is open they can score it. `JudgesService.setTracks` only rewrites `judge_tracks`; `ReviewsService.ownAssignment` checks only that the assignment is the caller's. The spec: _"A track judge must never see another track."_
**Fix:** in `ReviewsService.ownAssignment` and `queue`, also require `submission.trackId` to be null or one of the judge's current tracks. Optionally, in `setTracks`, delete _unstarted_ assignments outside the new tracks (same transaction, audited). Add an isolation-matrix row for this case. _Owner B (reviews) with A reviewing, about 45 min._

It still says 7/7, but it predates 22 commits. **Fix:** at the freeze commit, run `npm run acceptance` and commit the output (TEAM-PLAN §6, H68–H72). _Owner A._
